## 0. 这条链路要回答的问题

你写下这一行：

```rust
tbl.create_index(&["vector"], Index::Auto).execute().await?;
```

一行代码背后，到底发生了什么？谁选了 IVF_PQ 而不是 BTree？`num_partitions` 没填，是谁替你算了个默认值？最后"训练索引"这件重活，到底是 lancedb 自己干的，还是甩给了别人？

**这条链路要回答的核心只有一句**：lancedb **不实现任何索引算法**，它只负责"点单 → 分派 → 翻译参数 → 转交 lance"。真正的 IVF / PQ / HNSW / BTree 训练，全在 lance 后厨仓库完成。这是贯穿全库的主题——**组装而非重造**——在建索引这条链路上表现得最纯粹。

### 比喻锚点

沿用已建立的比喻家族：

- **服务员 `Table`**：接到"建索引"点单，自己不下厨，写一张点菜单递回。
- **点菜单 `IndexBuilder`**：攥着后厨的对讲机（`Arc<dyn BaseTable>`），喊一声 `execute()` 就把整张单子塞进后厨窗口。
- **用工合同 `BaseTable`**：第 453 条写明"后厨必须会建索引"。
- **后厨主管 `NativeTable`**：先看菜品类别（`match` 分派），派给对应灶台。
- **每个灶台师傅**干三件事：验菜（类型校验）→ 配料（参数兜底）→ 把订单翻译成中央仓库看得懂的工单（`*IndexParams`）。
- **金库保安 `DatasetConsistencyWrapper`**：师傅要动数据，先 `get_mut()` 拿可改写权限。
- **后厨仓库灶台 lance**：真正炒菜（训练索引）的地方。

## §1 入口：`Table::create_index` 与 `Index` 枚举

### 入口签名

`table.rs:761`：

```rust
pub fn create_index(&self, columns: &[impl AsRef<str>], index: Index) -> IndexBuilder {  // ① 不是 async！
    IndexBuilder::new(
        self.inner.clone(),                                  // ② 把后厨对讲机塞进点菜单
        columns
            .iter()
            .map(|val| val.as_ref().to_string())             // ③ 列名统一收成 Vec<String>
            .collect::<Vec<_>>(),
        index,                                               // ④ 你点的索引种类原样带上
    )
}
```

### 做了什么

注意 ①：**返回类型是 `IndexBuilder`，不是 `Future`，方法本身也不是 `async`**。它不碰任何 IO，只把"目标后厨句柄 + 列名 + 索引种类"组装成一张点菜单返回给你。真正下单要等你 `.execute().await`（见 §2）。

> **Rust 陷阱：`columns: &[impl AsRef<str>]`**。这是"接受任何能借成 `&str` 的元素切片"——`&["a"]`、`&[String]`、`&[&str]` 都能传。`impl Trait` 作参数 ≈ Python 的鸭子类型，但它在**编译期单态化**（每种实际类型生成一份专用代码），既灵活又零运行时开销。第一次见会困惑：把它读成"任何实现了 `AsRef<str>` 的类型"即可。

### `Index` 枚举：你能点哪些菜

`index.rs:23` 的 `Index` 是一个 **9 变体枚举**，每个非 `Auto` 变体内嵌一个对应的 Builder：

| `Index` 变体 | 行号 | 内嵌 Builder | 类别 | 一句话 |
|---|---|---|---|---|
| `Auto` | `index.rs:24` | （无） | 自动 | 让 lancedb 按列类型替你选 |
| `BTree(..)` | `:33` | `BTreeIndexBuilder` | 标量 | 排序索引，等值/范围查询 |
| `Bitmap(..)` | `:39` | `BitmapIndexBuilder` | 标量 | 低基数列位图 |
| `LabelList(..)` | `:44` | `LabelListIndexBuilder` | 标量 | `List<T>` 列的 contains 查询 |
| `FTS(..)` | `:47` | `FtsIndexBuilder` | 全文 | BM25 全文检索 |
| `IvfFlat(..)` | `:50` | `IvfFlatIndexBuilder` | 向量 | IVF 倒排，不压缩 |
| `IvfPq(..)` | `:53` | `IvfPqIndexBuilder` | 向量 | IVF + 乘积量化 |
| `IvfHnswPq(..)` | `:57` | `IvfHnswPqIndexBuilder` | 向量 | IVF-HNSW + PQ |
| `IvfHnswSq(..)` | `:61` | `IvfHnswSqIndexBuilder` | 向量 | IVF-HNSW + 标量量化 |

> **Rust 知识点：携带数据的枚举（tagged union）**。Rust 的 `enum` 不只是"一组常量名"，每个变体能**内嵌不同类型的负载**。`Index::IvfPq(IvfPqIndexBuilder)` 既标记了"我要 IVF_PQ"，又把那个 Builder 的全部配置一起带着走。类比：TypeScript 的可辨识联合（discriminated union），但 Rust 在编译期强制你 `match` 时处理每一个变体，漏一个都通不过编译。

## §2 `IndexBuilder`：收集列与配置（惰性）

### 点菜单的结构

`index.rs:67`：

```rust
pub struct IndexBuilder {
    parent: Arc<dyn BaseTable>,   // ① 后厨对讲机：运行期才知是 NativeTable 还是 RemoteTable
    pub(crate) index: Index,      // ② 你点的索引种类（携带其 Builder）
    pub(crate) columns: Vec<String>,
    pub(crate) replace: bool,     // ③ 是否覆盖同名索引
}
```

`new`（`index.rs:75`）只是把四个字段填上，**`replace` 默认 `true`**（`index.rs:80`）：

```rust
pub(crate) fn new(parent: Arc<dyn BaseTable>, columns: Vec<String>, index: Index) -> Self {
    Self { parent, index, columns, replace: true }   // 默认覆盖已有同名索引
}
```

你可以链式改它（`index.rs:89`）：

```rust
pub fn replace(mut self, v: bool) -> Self {   // mut self：消费自身再还回
    self.replace = v;
    self
}
```

`replace(false)` 的语义：若同名同列索引已存在则**报错**（哪怕它已过期），而非默默覆盖。

> **Rust 陷阱：`Arc<dyn BaseTable>` 是"动态分发的 trait 对象"**。`dyn BaseTable` 表示"某个实现了 `BaseTable` 合同的东西，具体是谁运行期才知道"，靠虚表（vtable）跳转。`Arc` 是引用计数指针，让多处共享同一后厨。类比 Java 接口引用 / Python ABC 实例，但 Rust 要显式写 `dyn` + 用 `Arc` 包起来。点菜单攥着这个句柄，就等于攥着后厨的对讲机。

### 发单：`execute` 把整张单子塞回后厨

`index.rs:94`：

```rust
pub async fn execute(self) -> Result<()> {                  // ① async + 按值取 self
    self.parent.clone().create_index(self).await            // ② 整张点菜单 move 回后厨
}
```

这一行虽短，藏了两个关键点：

1. **`execute(self)` 按值取 `self`（consume）**，不是 `&self`。调用后 `IndexBuilder` 被消耗、不可再用——这是 Builder 模式终结方法的标准约定。
2. **`self.parent.clone()` 再 `.create_index(self)`**：先 `clone` 出一份 `parent`（仅引用计数 +1，不深拷贝表），因为紧接着整个 `self`（含原 `parent` 字段）要被 `move` 进 `create_index`。不先 clone，调用对象就没了。

> **Rust 陷阱：`Arc::clone` 很便宜**。新人看到 `.clone()` 容易以为"复制了整张表"。其实 `Arc` 的 clone 只是原子地把引用计数 +1，背后还是同一个对象。这里 clone 纯粹是为了"在 `self` 被 move 走之前留住后厨句柄"。

> **比喻**：点菜单上喊一声"`execute()`"，整张单子（连同对讲机的复印件）被塞进后厨窗口。从这一刻起，控制权交给了后厨。

`self.parent.create_index(self)` 调用的是 `BaseTable` 合同里的 `create_index`——下一跳进入用工合同。

## §3 分派：合同方法 → 后厨按枚举选灶台

### 合同里的契约（A 段与 B 段的接缝）

`table.rs:453`：

```rust
async fn create_index(&self, index: IndexBuilder) -> Result<()>;   // BaseTable 合同第 453 条，只有声明没有方法体
```

这是 `BaseTable` trait（用工合同）里的一条抽象方法。它没有方法体——具体怎么建，由签了合同的后厨（`NativeTable` / `RemoteTable`）各自实现。`execute` 里那次 `self.parent.create_index(self)` 通过 **`dyn` 动态分发**，运行期跳到实际后厨的实现上。

> **Rust 知识点：`#[async_trait]` 风格的 async trait 方法**。trait 里写 `async fn`，本仓库靠 `#[async_trait]` 宏支持（见 `09` 篇 §1.1）。看到 trait 里有 `async fn` 不要以为是标准语法。

### 后厨总分派：`impl BaseTable for NativeTable::create_index`

`table.rs:1989`：

```rust
async fn create_index(&self, opts: IndexBuilder) -> Result<()> {
    if opts.columns.len() != 1 {                                  // ① 硬性拒绝多列复合索引
        return Err(Error::Schema {
            message: "Multi-column (composite) indices are not yet supported".to_string(),
        });
    }
    let schema = self.schema().await?;                            // ② 取 Arrow schema
    let field = schema.field_with_name(&opts.columns[0])?;        // ③ 取目标列的 Field（类型信息在这）

    match opts.index {                                            // ④ 按枚举分派到对应灶台
        Index::Auto => self.create_auto_index(field, opts).await,
        Index::BTree(_) => self.create_btree_index(field, opts).await,
        Index::Bitmap(_) => self.create_bitmap_index(field, opts).await,
        Index::LabelList(_) => self.create_label_list_index(field, opts).await,
        Index::FTS(fts_opts) => self.create_fts_index(field, fts_opts, opts.replace).await,
        Index::IvfFlat(ivf_flat) => self.create_ivf_flat_index(ivf_flat, field, opts.replace).await,
        Index::IvfPq(ivf_pq) => self.create_ivf_pq_index(ivf_pq, field, opts.replace).await,
        Index::IvfHnswPq(ivf_hnsw_pq) => self.create_ivf_hnsw_pq_index(ivf_hnsw_pq, field, opts.replace).await,
        Index::IvfHnswSq(ivf_hnsw_sq) => self.create_ivf_hnsw_sq_index(ivf_hnsw_sq, field, opts.replace).await,
    }
}
```

| `Auto` | `create_auto_index` :1660 | 智能选（向量→IvfPq / 标量→BTree） |
| `BTree` | `create_btree_index` :1677 | 标量灶 |

### `Index::Auto` 的智能选择：类型驱动分派

`table.rs:1660`：

```rust
async fn create_auto_index(&self, field: &Field, opts: IndexBuilder) -> Result<()> {
    if supported_vector_data_type(field.data_type()) {                       // ① 是向量列？
        self.create_ivf_pq_index(IvfPqIndexBuilder::default(), field, opts.replace).await   // → 默认 IVF_PQ
```

## §4 向量索引参数映射：校验、兜底、翻译

以 `create_ivf_pq_index`（`table.rs:1484`）为标准模板，三步走：

### 第一步：验菜（数据类型校验）

`table.rs:1490`：

```rust
if !supported_vector_data_type(field.data_type()) {
    return Err(Error::InvalidInput {
        message: format!("An IVF PQ index cannot be created on the column `{}` ...", field.name()),
    });
}
```

谓词 `supported_vector_data_type` 在 `utils.rs:174`：

```rust
pub fn supported_vector_data_type(dtype: &DataType) -> bool {
    match dtype {
        DataType::FixedSizeList(field, _) => {                                  // ① 定长列表（向量的标准存法）
            field.data_type().is_floating() || field.data_type() == &DataType::UInt8  // 元素须是浮点或 u8
        }
        DataType::List(field) => supported_vector_data_type(field.data_type()),  // ② 变长 List 递归往里看
        _ => false,
    }
}
```

即：向量列必须是 `FixedSizeList<float 或 UInt8>`，或递归包着它的 `List`。

### 第二步：配料（参数兜底，`suggested_*` 经验公式）

`table.rs:1500`–`1510`：

```rust
let num_partitions = if let Some(n) = index.num_partitions {      // ① 你填了就用你的
    n
} else {
    suggested_num_partitions(self.count_rows(None).await?)        // ② 没填就按行数估
};
let num_sub_vectors: u32 = if let Some(n) = index.num_sub_vectors {
    n
} else {
    let dim = infer_vector_dim(field.data_type())?;              // ③ 从列类型推出向量维度
    suggested_num_sub_vectors(dim as u32)                        // ④ 按维度估
};
```

两个经验公式在 `index/vector.rs`：

```rust
pub(crate) fn suggested_num_partitions(rows: usize) -> u32 {      // vector.rs:256
    let num_partitions = (rows as f64).sqrt() as u32;            // 分区数 = √行数
    max(1, num_partitions)                                       // 至少 1
}

pub(crate) fn suggested_num_sub_vectors(dim: u32) -> u32 {        // vector.rs:266
    if dim % 16 == 0 { dim / 16 }                                // 维度能被 16 整除 → dim/16
    else if dim % 8 == 0 { dim / 8 }                             // 否则能被 8 整除 → dim/8
    else { log::warn!("..."); 1 }                                // 都不行 → 1 并告警
}
```

> **HNSW 用不同的分区公式**。`create_ivf_hnsw_pq_index` / `create_ivf_hnsw_sq_index` 的分区数走 `suggested_num_partitions_for_hnsw(rows, dim)`（`vector.rs:261`）= `rows * dim / (256 * 5_000_000)`，且需要从 `FixedSizeList` 取出维度 `n`（`table.rs:1551` / `:1622`）。

> **给贡献者的信号**：`num_partitions` / `num_sub_vectors` 这两个经验公式**直接决定索引质量与构建速度**，且是贡献者最常改动的点。想优化默认行为，改 `vector.rs:256` / `:266` 这俩 `suggested_*` 即可，**无需碰 lance**。

> **Rust 知识点：`if let Some(n) = x { n } else { ... }`**。这是"有值就解包用、没值就走兜底"的惯用法，等价于其他语言的 `x ?? fallback`，但 Rust 用模式匹配解开 `Option<T>` 的 `Some`/`None` 两种情况。

### 第三步：翻译成 lance 工单 + 转交

`table.rs:1511`–`1527`：

>
> ```rust

> ```
>
> Python/JS 没有"由返回类型反推的隐式转换"，看不出转成了什么是正常的——记住"`.into()` 背后必有一个 `From` 实现，目标类型决定转成谁"。

> **⚠️ 两个同名 `IndexType` 是新人最易踩的坑**：

| 哪个 `IndexType` | 定义处 | 取值 | 用途 |
|---|---|---|---|
| lancedb 自己的 | `index.rs:100` | `IvfFlat/IvfPq/IvfHnswPq/IvfHnswSq/BTree/Bitmap/LabelList/FTS` | 元数据序列化、展示（带 serde alias） |
| lance_index 的 | `table.rs:43` `use lance_index::IndexType;` | `Vector/BTree/Bitmap/LabelList/Inverted` | 传给 lance `dataset.create_index` |

私有方法里传给 `dataset.create_index` 的那个永远是 **lance_index 的**。看到 `IndexType::Vector` / `IndexType::Inverted`，就是 lance 的那个（lancedb 自己的没有 `Vector` / `Inverted` 变体）。

## §5 IVF-PQ / HNSW / SQ 简介：Builder 如何映射到 lance BuildParams

四种向量索引的私有方法骨架完全一致（验菜 → 配料 → 翻译 → 转交），区别只在"翻译"那一步往 `VectorIndexParams` 喂什么。概念点到为止，重点看映射：

| 索引 | 私有方法 | lance 翻译点 | 喂给 lance 的 Params |
|---|---|---|---|
| IVF_FLAT | :1446 | `table.rs:1468` | `VectorIndexParams::ivf_flat(num_partitions, distance.into())` |
| IVF_PQ | :1484 | `table.rs:1512` | `VectorIndexParams::ivf_pq(num_partitions, num_bits=8, num_sub_vectors, distance.into(), max_iters)` |
| IVF_HNSW_PQ | :1531 | `table.rs:1584` | `VectorIndexParams::with_ivf_hnsw_pq_params(distance.into(), ivf_params, hnsw_params, pq_params)` |
| IVF_HNSW_SQ | :1602 | `table.rs:1642` | `VectorIndexParams::with_ivf_hnsw_sq_params(distance.into(), ivf_params, hnsw_params, sq_params)` |

HNSW 两支多一步"组装三个 BuildParams"。以 `create_ivf_hnsw_pq_index`（`table.rs:1574`–`1589`）为例：

```rust
let mut ivf_params = IvfBuildParams::new(num_partitions as usize);   // IVF 部分
ivf_params.sample_rate = index.sample_rate as usize;
ivf_params.max_iters = index.max_iterations as usize;
let hnsw_params = HnswBuildParams::default()                         // HNSW 图参数
    .num_edges(index.m as usize)                                     // m = 每个节点的边数
    .ef_construction(index.ef_construction as usize);                // 构图时的候选集大小
let pq_params = PQBuildParams {                                      // PQ 压缩参数
    num_sub_vectors: num_sub_vectors as usize,
    ..Default::default()
};
let lance_idx_params = VectorIndexParams::with_ivf_hnsw_pq_params(   // 三者合成 lance 工单
    index.distance_type.into(), ivf_params, hnsw_params, pq_params,
);
```

`IvfBuildParams` / `HnswBuildParams` / `PQBuildParams` / `SQBuildParams` 全是 **lance 的类型**——lancedb 只是把自己 Builder 上的字段（`m`、`ef_construction`、`sample_rate`、`num_sub_vectors`…）逐个搬进去。**没有一行真正的建图/量化算法。**

> **向量 Builder 的 setter 用宏批量生成**。四个向量 Builder（`IvfFlat/IvfPq/IvfHnswPq/IvfHnswSq`）的链式方法不是手写的，而是用 `macro_rules!` 生成：`impl_distance_type_setter!` / `impl_ivf_params_setter!` / `impl_pq_params_setter!` / `impl_hnsw_params_setter!`（定义在 `vector.rs:48` / `:67` / `:118` / `:143`，按需 invoke，如 `vector.rs:251`–`253`）。
>
> **Rust 知识点：声明宏 `macro_rules!`**。它在编译期"展开"成代码，用来消除重复样板——四个 Builder 都需要 `.distance_type(..)` setter，与其手写四遍，不如写一个宏 invoke 四次。类比 C 的宏，但 Rust 的宏是**卫生的（hygienic）**、按语法树工作，不会像 C 那样意外捕获变量。

## §6 标量索引链路：BTree / Bitmap / LabelList / FTS

标量灶比向量灶更简单——**没有参数兜底**，因为 `BTreeIndexBuilder` / `BitmapIndexBuilder` / `LabelListIndexBuilder` 都是**空结构体**（`scalar.rs:31` / `:43` / `:52`）：

```rust
#[derive(Default, Debug, Clone)]
pub struct BTreeIndexBuilder {}     // scalar.rs:31 —— 空的！目前无可调参数
```

> **Rust 陷阱：空结构体有什么用？** `struct BTreeIndexBuilder {}` 看似无意义，实为**类型级标记（type-level tag）**：让 `Index::BTree(BTreeIndexBuilder)` 这个变体携带类型信息，也为将来加字段（如注释里提到的 block size）留出空间——加了字段也不破坏现有 API。新人会奇怪"为何要空 struct"，答案是"占位 + 类型标记"。

三个标量索引的私有方法（`create_btree_index` :1677 / `create_bitmap_index` :1704 / `create_label_list_index` :1731）骨架一致：**验菜 → 拿写锁 → 强制类型 → 转交**。以 BTree 为例（`table.rs:1688`–`1700`）：

```rust
let mut dataset = self.dataset.get_mut().await?;
let lance_idx_params = lance_index::scalar::ScalarIndexParams {        // 统一用 ScalarIndexParams
    force_index_type: Some(lance_index::scalar::ScalarIndexType::BTree),  // 强制指定为 BTree
};
dataset.create_index(&[field.name()], IndexType::BTree, None, &lance_idx_params, opts.replace).await?;
```

三者只差一个 `force_index_type` 和那个 lance `IndexType`：

| 索引 | 验菜谓词（`utils.rs`） | `force_index_type` | lance `IndexType` |
|---|---|---|---|
| BTree | `supported_btree_data_type` :132 | `ScalarIndexType::BTree` (table.rs:1690) | `IndexType::BTree` (:1695) |
| Bitmap | `supported_bitmap_data_type` :148 | `ScalarIndexType::Bitmap` (:1717) | `IndexType::Bitmap` (:1722) |
| LabelList | `supported_label_list_data_type` :152 | `ScalarIndexType::LabelList` (:1744) | `IndexType::LabelList` (:1749) |

验菜谓词决定了"哪些列类型能建"：

- `supported_btree_data_type`（`utils.rs:132`）：整数 / 浮点 / `Boolean` / `Utf8` / 时间日期 / `FixedSizeBinary`。
- `supported_bitmap_data_type`（`utils.rs:148`）：只接整数或 `Utf8`。
- `supported_label_list_data_type`（`utils.rs:152`）：`List`/`FixedSizeList`，且其元素满足 bitmap 条件。

### FTS：唯一带配置的标量索引

`create_fts_index`（`table.rs:1758`）略有不同——它走**倒排索引**，且 `FtsIndexBuilder` 真有字段（`scalar.rs:58`，`with_position` 默认 `true` 见 `scalar.rs:69`）：

```rust
if !supported_fts_data_type(field.data_type()) { /* 报错 */ }        // 验菜：utils.rs:160，只接 Utf8/LargeUtf8 或其 List
let mut dataset = self.dataset.get_mut().await?;
let fts_params = lance_index::scalar::InvertedIndexParams {           // table.rs:1775，注意是 Inverted 不是 Scalar
    with_position: fts_opts.with_position,                           // 是否存 token 位置（短语查询要）
    tokenizer_config: fts_opts.tokenizer_configs,
};
dataset.create_index(&[field.name()], IndexType::Inverted, None, &fts_params, replace).await?;  // :1782
```

> **Rust 知识点：元组模式匹配 + 或模式**。`supported_fts_data_type_impl`（`utils.rs:164`）对 `(dtype, in_list)` 元组做 `match`，里面 `DataType::Utf8 | DataType::LargeUtf8` 的 `|` 是**或模式**——一个分支同时匹配多个变体。这是 Rust 写多条件分支的惯用法，比连写多个 `if` 干净得多。

## §7 委托 lance：真正训练 / 构建索引

无论哪条灶台，最后一跳都长一个样（`table.rs:1519` / `:1692` / `:1779` 等）：

```rust
let mut dataset = self.dataset.get_mut().await?;                          // ① 金库保安拿可变 Dataset
dataset.create_index(&[field.name()], <lance IndexType>, None, &params, replace).await?;  // ② 转交 lance
```

到这里，**lancedb 的活全干完了**。它做的全部就是：校验类型 + 兜底参数 + 翻译成 lance 的 `*IndexParams`。真正的 IVF 聚类、PQ 码本训练、HNSW 建图、BTree 排序落盘——**全在 lance `Dataset::create_index` 内部完成**，这条链路就此跨出 lancedb 边界。

> **Rust 知识点：内部可变性**。`create_index` 的签名是 `&self`（不可变借用），却能改数据。秘密在 `self.dataset.get_mut()`——可变性藏在 `DatasetConsistencyWrapper` 内部的 `RwLock` 里（见 `09` 篇 §4.1）。"对外 `&self`、对内拿写锁改"就是内部可变性，是 Rust 并发的核心套路。锁的细节留给 `10 Table 解剖（下）`。

> **组装而非重造的字面证据**：把 `table.rs:1512`（向量）、`:1689`（标量）、`:1775`（FTS）三处并排看，会发现私有方法**没有一行索引算法**，全是"翻译 + 转交"。这正是 README 那句"组装而非重造"在建索引链路上的铁证——lancedb 是把客人的话翻译成厨房工单的餐厅经理，不是炒菜的厨师。

## 小结 & 下一篇

- **建索引链路 = 同步点菜 + 异步下厨**：`Table::create_index`（`table.rs:761`）同步只造 `IndexBuilder`；`IndexBuilder::execute`（`index.rs:94`）才把整张单子 move 回后厨。这是 lancedb `builder.xxx().execute().await` 三段式 API 的范本。
- **总路由表在 `table.rs:1999`**：`NativeTable::create_index` 的 `match opts.index` 一眼定位每个 `Index` 变体走哪个私有方法。读"一个入口多种实现"的链路，先找这张 `match`。
- **每个灶台只干三件事**：验菜（`supported_*_data_type`）→ 配料（`suggested_*` 兜底）→ 翻译成 lance 的 `*IndexParams` → 转交 `dataset.create_index`。**没有一行索引算法**——组装而非重造。
- **两个易混点**：①两个同名 `IndexType`（lancedb `index.rs:100` 用于展示 vs lance_index `table.rs:43` 传给 lance）；②`.into()` 隐式把 `DistanceType` 转成 `LanceDistanceType`（`lib.rs:255`）。

**下一篇**：可深潜 lance 内部 `Dataset::create_index` 如何真正训练 IVF / PQ / HNSW（出 lancedb 仓库）；或回到 `10 Table 解剖（下）` 看 `self.dataset.get_mut()` 背后金库保安 `DatasetConsistencyWrapper` 的读写锁与一致性机制——本篇所有灶台最后那把写锁，到底怎么保证账本一致。
